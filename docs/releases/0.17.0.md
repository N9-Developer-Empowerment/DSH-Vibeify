# Vibeify 0.17.0 — DeepSeek leads, OpenAI supports

Vibeify 0.17.0 adds a native DeepSeek-led setup with optional ChatGPT-authenticated Codex support. DeepSeek V4.1 Flash 1017 leads through the `deepseek-flash` alias. When useful, the lead can send a bounded task to GPT-6.1 Sol (`gpt-6.1-sol`) and review its returned evidence before deciding what to use. DeepSeek remains responsible for the conversation and final answer.

## What changed

- Added the separate `dsh-vibeify-deepseek` bundle and **Vibeify DeepSeek** preset. The original **Standard** preset remains available.
- Added the native `@deepseek-ai/dsh-subagent-codex` route with GPT-6.1 Sol as the optional one-shot worker model. Model discovery is through the qualified Codex app-server using the existing ChatGPT sign-in.
- Qualified the bundle against DeepSeek Harness `0.2.1-rc.2`, Codex `0.164.0`, and Vibeify `0.17.0`.
- Updated the Mac, Windows and Linux installers so **Both** means DeepSeek leads and OpenAI supports bounded tasks. **ChatGPT only** remains the Codex-led choice; **DeepSeek only** remains the native route without Codex worker support.
- Refined the BBC-inspired magazine appearance and matching shared-article typography, image spacing and editorial hierarchy.
- Updated install guidance to keep Windows and Linux clearly marked as preview until their complete routes pass on real machines.

## Worker boundaries

The native Codex worker is one-shot and unattended. It uses `approve-for-me`, which runs in a workspace-write sandbox and routes eligible permission requests through Codex automatic review. It does not use the dangerous sandbox bypass. Requests requiring human input or protected connected-app approval fail closed and return to the lead's normal confirmation route. The instruction to use no more than two workers is policy guidance, not a hard runtime cap.

DeepSeek API usage and ChatGPT plan usage are separate. This release makes no promise of lower total cost or identical quality for every task; the lead must decide whether the worker evidence is suitable.

## Installation

On macOS, use the friendly installer and choose **Both — DeepSeek leads; OpenAI supports suitable work**. Connect DeepSeek under DSH **Settings → Models** and complete ChatGPT sign-in if you want the optional worker.

For a checked-out source tree:

```bash
./scripts/install-dsh.sh --replace
./scripts/install-vibeify.sh --provider deepseek-codex
./scripts/doctor.sh
```

Finish active work before activation. Use a fresh session to pick up the new preset; existing sessions retain their existing composition. See [Installation](../INSTALL.md) and the [FAQ](../FAQ.md).

## Validation status

The release preparation passed 292 core behavior checks, generated-client checks, native routing and package checks, installer source and choice fixtures, fresh-profile installation fixtures, archive construction, and local server authentication checks. The pull request's GitHub checks are the release gate; see the repository's [installer and runtime workflow](../../.github/workflows/test-installers.yml).

A local synthetic delegation check on this compatibility bundle sent `19 × 23` to the GPT-6.1 Sol worker, which returned `437`; the DeepSeek lead independently checked the arithmetic and returned `DEEPSEEK_LEAD_OK / SOL_WORKER_OK=437`. This verifies one bounded native delegation, not every task or platform.

Windows and Linux remain preview platforms until real-machine acceptance is complete. A source test or Mac simulation does not qualify those platforms.
